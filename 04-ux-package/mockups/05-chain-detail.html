How this chain works · EN

A request handler at POST /v1/uploads accepts a user-supplied URL and fetches it server-side without validating the host. An attacker submits http://169.254.169.254/latest/meta-data/iam/security-credentials/edge-tasks and receives temporary AWS credentials for the edge-tasks IAM role. That role has s3:GetObject on scb-edge-receipts, a bucket containing 218,442 customer receipt PDFs with citizen ID and phone number in the OCR'd text layer. Critic agent independently re-derived the chain via an alternate proxy path and confirmed reachability.

Business impact · ผลกระทบเชิงธุรกิจ

  • PDPA Art. 37 — confirmed exfil of citizen ID + phone triggers 72-hour breach notification.
  • BoT IT Risk Guideline §5 — material weakness in customer-data control.
  • PCI DSS 4.0 Req. 1.4 / 6.4.1 — SSRF in scoped CDE flow.
  • Reputational: 218,442 customers affected if exfil were achieved.
  • Regulatory penalty exposure: up to THB 5,000,000 per PDPA breach event.

Remediation · การแก้ไข

  1. Force IMDSv2 on all EC2 in edge-* ASG — eliminates the metadata route entirely.
  2. Validate URL host in /v1/uploads: deny RFC1918 + link-local, allow-list of approved hosts.
  3. Tighten IAM: edge-tasks should not have s3:GetObject on the receipts bucket — split write-only role.
  4. Enable S3 Block Public Access + bucket-owner-enforced ACL on scb-edge-receipts.
  5. Add WAF rule to block link-local URLs in upload payloads.
